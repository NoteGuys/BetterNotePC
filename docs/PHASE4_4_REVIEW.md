## พฤติกรรมที่เปลี่ยน

1. สมุดมีตัวจัดการเลื่อนหลักที่ NoteEditor จุดเดียว แทน CanvasBoard กับ stage จัดการซ้อนกัน ใช้หนึ่งนิ้วเลื่อนสมุดตามเดิม; Whiteboard คง Hand หรือสองนิ้วสำหรับเลื่อน
2. การเลื่อน/ซูมไม่บังคับรอ 1.2 วินาทีหลังปากกาทุกครั้ง ติดตาม ID ของสัมผัสที่อยู่ระหว่างเขียนและบล็อกจนยกนิ้วนั้นจริง สัมผัสใหม่หลังยกปากกาเริ่ม navigation ได้ทันที เงื่อนไขเมนูวาง/ป้องกันเมาส์จำลองเดิมยังคงไว้
3. ปากกา/ลากวัตถุมีลำดับสำคัญเหนือ navigation ยกเลิก inertia/RAF/preview ที่ค้างก่อนเริ่มเขียน ไม่แก้หรือทิ้งข้อมูลรอยปากกาที่รับแล้ว
4. ซูมสมุดด้วย CSS preview ตามเฟรม แล้ววัดตำแหน่งหน้าจริงหลัง React ใช้ zoom เพื่อรักษาจุดใต้ midpoint รวมหน้าที่จัดกึ่งกลางและช่องว่างระหว่างหน้าแนวตั้ง ไม่ใช้เพียง scrollTop * อัตราซูม
5. ทัชแพด Ctrl+wheel ซูมตรงจุดเมาส์ รวมเหตุการณ์ต่อเฟรม และ normalize deltaMode ของอุปกรณ์
6. เมื่อหน้าแนวนอนใหญ่กว่าพื้นที่มองเห็น ล้อเมาส์เลื่อนภายในหน้าก่อน เมื่อหน้าอยู่ครบในพื้นที่จึงใช้ล้อเปลี่ยนหน้า สะสมระยะ 40 px และให้หนึ่งหน้าต่อกลุ่มเหตุการณ์ต่อเนื่อง ช่องว่างเกิน 220 ms เริ่มกลุ่มใหม่ กันแรงเลื่อนท้ายทัชแพดพลิกหลายหน้า
7. การเลื่อนนิ้วมี threshold 16 px และ inertia ตามเวลาจริง จำกัดความเร็ว หยุดเมื่อสุดขอบ/เริ่มปากกา/มีสัมผัสใหม่/เปลี่ยนหน้าด้วยคำสั่ง/สลับหน้าต่าง
8. ใช้เกณฑ์แตะสองนิ้วสองครั้งร่วมกันในสมุดและ Whiteboard รองรับนิ้วลงห่างกันไม่เกิน 160 ms และยกไม่พร้อมกัน แต่ต้องไม่มีการเคลื่อนเกิน 8 px, นิ้วที่สาม, ยกเลิก, pen/drag lock หรือสลับหน้าต่าง เมื่อรู้จำว่าเป็นการซูมจะล้าง tap candidate ทันที แม้นิ้วแต่ละข้างขยับเพียง 5 px แต่ระยะระหว่างนิ้วเปลี่ยนเกินเกณฑ์ การเลื่อน/ซูมไม่สร้างประวัติเนื้อหา
9. ยกนิ้วจากสองเหลือหนึ่งไม่เปลี่ยนเป็นการลากใหม่โดยเงียบ ๆ ให้จบท่าทางเดิมก่อนเริ่มสัมผัสใหม่
10. blur/ซ่อนหน้าต่าง/unmount/เปลี่ยนเครื่องมือ/เลือกหน้า และสัมผัสจบนอกกระดาษยกเลิกงานค้าง ไม่ให้ touchcancel กลายเป็น Undo ติดตามฝ่ามือเดิมต่อแต่ปลดจำนวน live contacts ที่ค้างจากหน้าต่างเก่า เพื่อไม่ให้ wheel ล็อกจนต้องแตะจอซ้ำ

## ผลตรวจอัตโนมัติ

| ชุดตรวจ | ผล |
| --- | --- |
| Navigation ผ่าน React/สมุด/Whiteboard จริงใน Browser, โปรไฟล์แยก | 30 ผ่าน |
| ชุด navigation เดียวกันใน Electron จริง file://, หน้าต่างซ่อน, โปรไฟล์แยก | 30 ผ่าน |
| ปากกา/ไฮไลต์/รูปทรง/คืนล็อกเดิม | 84 ผ่านใน Browser และ Electron |
| Editor/IndexedDB/Undo/Redo/แท็บ/UI เดิม | 133 ผ่าน |
| Unit สัมผัส + geometry/history/local-save/cover | 72 ผ่าน |
| Production build | ผ่าน 2,142 modules |

Navigation รวมการเลื่อนทั้งบนกระดาษและพื้นหลัง, ฝ่ามือค้าง/แตะใหม่หลังปากกา, pen ตัด inertia, พิกัดหลังซูมจริงแนวตั้ง/แนวนอน, รูปแบบแตะ/ยกนิ้ว, ยกเลิกไม่ Undo, blur, เลือกหน้า, unmount, wheel tail, zoomed-page pan, Ctrl-wheel ระหว่างปากกา, object lock และการจบสัมผัสนอกกระดาษ/หายไปเมื่อ blur ไม่มี unhandled renderer error

ทดสอบด้วย PointerEvent/TouchEvent จำลองผ่าน component จริงและฐานข้อมูลจำลองเท่านั้น ไม่เปิดโปรไฟล์แอปที่ติดตั้ง ไม่เข้าถึง Drive หรือโน้ตจริง ไม่มีเครือข่ายในชุด navigation
หน้าต่าง Electron ทดสอบซ่อนและตั้ง backgroundThrottling=false เฉพาะตัว harness; รอผล zoom จริงแทนการสมมติว่าเฟรมเสร็จใน 80 ms และควบคุม RAF เมื่อวัด burst ไม่เปลี่ยน Electron main ของแอป

## ให้ผู้ใช้ตรวจบนเครื่อง

ปิดแล้วเปิดตัวทดสอบจาก workspace ที่ build ล่าสุด ตัวติดตั้งเก่าไม่ได้อัปเดตอัตโนมัติ

1. เขียนโดยวางฝ่ามือ แล้วลองขยับมือ: หน้าต้องไม่เลื่อนเอง ยกปากกาและยกนิ้วเดิม แล้วแตะใหม่เพื่อเลื่อน/ซูมได้ทันที
2. ซูมด้วยสองนิ้ว เลื่อนพร้อมซูม และยกนิ้วไม่พร้อมกัน จากนั้นเขียนต่อ ทั้งสมุดและ Whiteboard: ตำแหน่งไม่กระโดด ไม่มี Undo เอง ลองสลับหน้าต่างแล้วกลับมา
3. ล้อเมาส์/ทัชแพดในหน้าเล็กและหน้าขยาย: กวาดหนึ่งครั้งไม่พลิกหลายหน้า เมื่อขยายควรเลื่อนอ่านภายในหน้า ลอง Ctrl+wheel และแตะสองนิ้วสองครั้งเพื่อ Undo ตามตั้งใจ

ตรงขอบพื้นที่เลื่อน เบราว์เซอร์จำกัด scroll ตามขนาดเนื้อหา จึงรักษาจุดใต้มือได้เท่าที่ขอบเขตอนุญาต คงขอบเขต zoom เดิมของแต่ละโหมดไว้
ยังต้องตรวจการกันฝ่ามือและความรู้สึกบน digitizer/ทัชแพดจริงก่อนปิดผลฮาร์ดแวร์เฟส 4; งาน RAM/เอกสารใหญ่เฟส 5 ยังไม่เริ่ม
