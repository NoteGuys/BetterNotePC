# ทดสอบ BetterNote Sol Prework บน Surface Intel — 1.3.1.0

ตัวนี้สร้างจาก working tree ของ `sol-prework` รวม Optimize, PDF และภาษา/Settings ที่ตรวจไว้ เมื่อ 18 ตุลาคม 2026 ใช้ Electron x64 สำหรับ Surface Intel ไม่ใช่แพ็กเกจ Microsoft Store รุ่นเผยแพร่

## ติดตั้งและเตรียมข้อมูล

1. คัดลอก `BetterNote-Sol-Prework-1.3.1.0-Surface-Intel-Setup.exe` ไป Surface แล้วดับเบิลคลิก ติดตั้งตามหน้าจอ เปิดจากทางลัด **BetterNote Sol Prework (Test)**
2. ตัวทดสอบมีชื่อและตัวติดตั้งแยกจาก BetterNote รุ่นใช้งานจริง ไม่ต้องถอนรุ่นจริงก่อน เลือกโฟลเดอร์ติดตั้งของตัวทดสอบเอง อย่าเลือกโฟลเดอร์ของรุ่นจริง
3. ข้อมูลตัวทดสอบอยู่ที่ `%APPDATA%\BetterNote-Sol-Prework\Profile` และโฟลเดอร์สำรองเริ่มต้นอยู่ใต้ `%APPDATA%\BetterNote-Sol-Prework\Documents\BetterNote.AppPC` การเปิดครั้งแรกจึงไม่เห็นสมุดของรุ่นจริง ถือว่าปกติ
4. เริ่มด้วยสำเนาสมุด/PDF ที่รู้เนื้อหา เช่น PDF 80–100 หน้า รูปหนึ่งรูป และสมุดว่างหนึ่งเล่ม นำเข้าไฟล์สำเนาหรือ Restore สำเนาชุดสำรองด้วยตัวเอง
5. สำหรับ Local Backup เลือกโฟลเดอร์ใหม่ เช่น `Documents\BetterNote-Sol-Test-Backup` สำหรับ Google Drive ให้สร้างโฟลเดอร์ใหม่ เช่น `My Drive\BetterNote-Sol-Test` ใช้ปลายทางทดสอบเดียวกันบน Surface และ PC หลีกเลี่ยงการเลือกโฟลเดอร์สำรองงานจริง เพราะการเลือกเองสามารถทำให้ตัวทดสอบเขียนไฟล์ในปลายทางนั้นได้
6. หาก Windows แจ้งว่าไม่รู้จักผู้เผยแพร่ ตัวทดสอบนี้ไม่มีลายเซ็นดิจิทัล ตรวจว่าเป็นไฟล์ที่รับจากงานนี้ก่อนดำเนินการต่อ

## รอบหลัก — การเขียนและการเซฟ (ประมาณ 15 นาที)

| ลำดับ | ลงมือทดสอบ | ผลที่ควรได้ |
|---|---|---|
| 1 | สร้างสมุด เขียนตัวเลข/วงกลม/เส้นยาวด้วยปากกา ลองเร็วและช้า น้ำหนักเบาและหนัก ปากกาแต่ละหัวและไฮไลต์ | ระหว่างลากกับหลังยกปากกาลายเส้นต่อเนื่อง ไม่กระโดดหรือหาย |
| 2 | เขียนเส้นยาวต่อเนื่องสลับจุดสั้น ๆ Undo/Redo แล้วใช้ยางลบและ Lasso ย้ายเส้น | ย้อนกลับ/ทำซ้ำตรงตามลำดับ สี ความหนา และตำแหน่งถูกต้อง |
| 3 | วางรูป หมุน/ปรับขนาด/ย้าย เพิ่มข้อความ แล้วสลับหน้า/แท็บ/กลับหน้าแรกหลายครั้ง | รูป ข้อความ และเส้นอยู่ครบ ไม่มีภาพดำหรือหน้าขาวค้าง |
| 4 | เขียนเส้นสุดท้ายแล้วกด X ปิดทันที จากนั้นเปิดใหม่ ทำซ้ำอีกครั้งโดยย่อหน้าต่างก่อนปิด | เส้นสุดท้ายอยู่ครบ เปิดใหม่ได้ และไม่มี JavaScript error ตอนปิด |
| 5 | ทดสอบข้อ 1–4 ทั้งสมุดปกติและ Whiteboard | พฤติกรรมการเขียนและการเก็บข้อมูลเหมือนเดิม |

## ปากกา นิ้ว และพื้นที่จอจริง (ประมาณ 10 นาที)

- ใช้ความละเอียด/Windows scaling ที่ใช้เรียนจริง และลองย่อหน้าต่าง ตรวจแถบเครื่องมือให้อยู่บรรทัดเดียวตามพื้นที่ ปุ่มที่เล็งด้วยปากกากดติด ไม่ซ้อนหรือหลุดขอบ
- เขียนด้วยมือขวา ยกปากกาออกจากจอ แล้วใช้นิ้วมือซ้ายเลื่อน/ซูมบริเวณไกลจากจุดที่เขียน จากนั้นสลับมือ ทดสอบทั้ง Whiteboard และสมุดปกติ ต้องรับสัมผัสทั่วพื้นที่ ไม่ต้องแตะซ้ำหลายครั้ง
- วางฝ่ามือขณะเขียน ตรวจว่าไม่เกิดเส้นจากฝ่ามือ ทดสอบเปิด/ปิดโหมดโล่และโหมดมือให้ตรงกับการใช้งานเดิม
- ซูมเข้า–ออก เปลี่ยนหน้าต่อเนื่องประมาณ 30 ครั้ง และกลับมาหน้าแรกของเอกสาร ต้องไม่ดำหรือเบลอค้าง
- เปิด Export แล้วกด X ด้วยปากกา รวมทั้งปุ่มเลือกสี/ความหนาและเมนูย่อย ต้องปิด/เลือกได้ตามปกติ

## PDF และภาพ (ประมาณ 15 นาที)

1. นำเข้า PDF ขนาด 80–100 หน้า เปิดหน้าแรก กลาง และท้าย ตรวจลำดับ ขนาดหน้า ตัวหนังสือ และความชัด ขณะนำเข้าต้องมีสถานะทำงาน ไม่ต้องกดย้ำ
2. เขียนวงกลม ลูกศร เส้นโค้ง จุดสั้น เส้นหนา/บาง และไฮไลต์บน PDF ทดสอบทั้งหน้าแนวตั้ง/แนวนอนที่มีอยู่ในไฟล์
3. Export หน้าปัจจุบันและทั้งสมุด เปิดด้วย **Microsoft Edge** ซูม 100%, 300% และ 500% เปรียบเทียบกับในแอป: เส้นต้องไม่แตกเป็นปล้อง/รอยฟัน รูปและข้อความไม่หาย ไฮไลต์ไม่ทึบผิดปกติ และหน้าครบ
4. สั่ง Export จากเมนูหน้าคลังด้วย หลอดความคืบหน้าต้องหายเมื่อเสร็จหรือยกเลิก และคำสั่งครั้งต่อไปต้องทำงานได้
5. นำเข้ารูปที่ใช้สอนจริงหนึ่งรูปและรูปความละเอียดสูงอีกหนึ่งรูป ย้าย/ย่อ–ขยาย แล้วปิด–เปิด ตรวจภาพยังอยู่ ไม่ต้องใช้รูปใหญ่ผิดปกติเพื่อฝืน RAM ของเครื่อง
6. ส่งออก `.bnote` ของสมุดทดสอบ แล้วนำเข้าในตัวทดสอบ ตรวจเส้น ข้อความ รูป และหน้าครบ การนำเข้าอยู่ในคลังโดยไม่เปิดทันทีเป็นพฤติกรรมที่ตั้งใจไว้

## Backup เฉพาะงานที่เปลี่ยน (ประมาณ 15 นาที)

1. เลือกโฟลเดอร์ทดสอบใหม่ กด Back up now **ครั้งเดียว** ต้องแสดงว่ารับคำสั่งแล้ว รอสำรองข้อมูลและ PDF รอบแรกให้เสร็จ รอบแรกที่ต้องสร้าง PDF ทุกหน้ายังใช้เวลาได้
2. กดซ้ำโดยไม่ได้แก้สมุด ต้องใช้ไฟล์/PDF ที่ยังตรงกับข้อมูลเดิม ไม่สร้าง PDF ทุกหน้าใหม่ ตรวจด้วย Show file และเวลาแก้ไขไฟล์ประกอบ
3. แก้เพียงหน้าเดียวในสมุดใหญ่ แล้วกด Backup ต้องอัปเดตสมุดที่เปลี่ยนและ PDF ของหน้านั้น โดยใช้ PDF cache ของหน้าอื่นที่ยังตรงอยู่ ข้อมูลสำรองทั้งคลัง/metadata อาจเปลี่ยนตามได้ จึงไม่คาดว่าทุกไฟล์ในโฟลเดอร์จะมีเวลาเดิมทั้งหมด
4. ลองแก้ข้อความ เปลี่ยนขนาด/ตำแหน่งรูป เพิ่ม/ลบเส้น แล้วสำรองอีกครั้ง ต้องได้การเปลี่ยนแปลงเหล่านี้ครบ
5. ระหว่างสำรอง ลองเขียนและเปลี่ยนหน้า ต้องยังใช้งานได้ หลังงานเบื้องหลังเสร็จ PDF ต้องสะท้อนข้อมูลล่าสุด หรือมีรอบอัปเดตต่อจนตรง ไม่มีสถานะว่าสำเร็จทั้งที่ไฟล์ยังเก่า
6. ปุ่ม Show file ต้องเปิดโฟลเดอร์และชี้ไฟล์ที่ถูกต้อง ส่วนปุ่ม Backup ในหน้า Google Drive ต้องใช้ได้

## Restore ข้าม Surface ↔ PC (ประมาณ 20 นาทีและเวลาซิงค์)

ใช้ตัวทดสอบบนทั้งสองเครื่องและโฟลเดอร์ Drive ทดสอบเดียวกัน รอ Google Drive ซิงค์เสร็จ หากไฟล์เป็นออนไลน์อย่างเดียว ให้ลองทดสอบทั้งหลังทำ Available offline และการดาวน์โหลดตามปกติ บันทึกความต่างไว้

| เหตุการณ์ | ผลที่ต้องตรวจ |
|---|---|
| Surface สร้างสมุด A เขียนคำว่า Surface-1 → Backup → PC เลือก device ของ Surface แล้ว Restore | เนื้อหาครบ โฟลเดอร์ถูกที่ ไม่ค้างที่ Checking โดยไม่มีความคืบหน้าตลอดไป |
| PC รับ A แล้วเพิ่ม PC-2 → Backup → Surface Restore จาก PC โดยไม่ได้แก้ A ต่อเอง | ได้ PC-2 และไม่เกิดสำเนา “Copy from this device” โดยไม่จำเป็น |
| กด Restore ชุดเดิมซ้ำ แล้วเปิดตัวเลือก device อีกครั้ง | เมนู device เลือกได้ งานไม่ซ้ำเพิ่มเอง |
| แก้ A คนละอย่างทั้งสองเครื่องก่อน Restore | งานที่แตกต่างทั้งสองฝั่งยังมีทางเก็บรักษา ไม่เขียนทับทิ้งเงียบ ๆ กรณีนี้การมีสำเนาเพื่อเก็บงานขัดแย้งอาจเป็นพฤติกรรมที่ถูกต้อง |
| สร้างโฟลเดอร์และสมุดย่อย ลบและล้างขยะของข้อมูลทดสอบ จากนั้น Backup และ Restore ชุดใหม่ | ข้อมูลที่ลบแล้วไม่กลับมา โฟลเดอร์อื่นไม่ย้ายไปอยู่ใต้ Lecture Notes หรือโฟลเดอร์ผิด |
| ปิด–เปิดทั้งสองเครื่อง | ไม่มี Restore อัตโนมัติ และไม่มีแถบชวน Restore ซ้ำทุกครั้ง |
| ปลายทาง Drive ยังไม่พร้อม/อินเทอร์เน็ตหลุด | แจ้งเหตุและให้ลองใหม่ได้ งานเดิมยังอยู่ ไม่บอกว่า backup ขึ้นคลาวด์สำเร็จทั้งที่ยืนยันไม่ได้ |

อย่าจงใจขัดจังหวะด้วยการลบไฟล์สำรองงานจริง ทดสอบชุดเสีย/ไฟล์ขาดเฉพาะสำเนาในโฟลเดอร์ QA และหยุดเมื่อพบข้อมูลไม่ตรง

## ภาษา คู่มือ และ Settings (ประมาณ 10 นาที)

- ลองภาษาเดิมที่ใช้ แล้วสลับ Spanish, German และ Arabic (รุ่นทดสอบ) ตรวจปุ่ม/กล่องข้อความไม่ถูกตัดหรือมี key แปลหลุด ปิด–เปิดแล้วยังจำภาษาเดิม
- ภาษาอาหรับให้ดูเมนู/การจัดข้อความขวาไปซ้าย ส่วนตำแหน่งเส้น รูป หน้ากระดาษ และเครื่องมือเขียนต้องยังสอดคล้องกับที่กด
- เปิดคู่มือใต้ Favorites เลือกหมวด Backup/Restore, การเขียน และ PDF ตรวจภาพซูม ลูกศร เนื้อหา การค้นหา และการย้อนกลับ ลองธีมสว่าง/มืด
- Settings ต้องเลื่อนดูส่วนล่างได้บน Surface ปุ่ม GitHub แบบวงกลมเปิดหน้า Releases/ข้อเสนอแนะของ BetterNote-Releases ตามที่เลือก ไม่ใช่ repository โค้ดแอป
- ตรวจเลขรุ่น 1.3.1.0 ใน Updates & Version การเช็กอัปเดตของตัวทดสอบที่ติดตั้งนอก Store อาจแจ้งว่าเช็กไม่ได้ ไม่ใช้กรณีนี้ตัดสินการอัปเดตของแพ็กเกจ Store

## ใช้สอนจริงและสังเกตทรัพยากร (อย่างน้อย 30 นาที)

1. เปิด Task Manager ดูหน่วยความจำรวมของกลุ่ม BetterNote และ CPU จดหลังเปิดคลัง หลังเปิด PDF และหลังใช้งาน 10/20/30 นาที
2. ใช้เขียน เปลี่ยนหน้า Undo/Redo วางรูป และกลับหน้าแรกเหมือนใช้สอนจริง เริ่มทดสอบแอปเดี่ยวก่อน
3. จากนั้นเปิด Teams และแชร์หน้าจอแบบที่อาจารย์ใช้ ทำงานแบบเดิมอีกช่วงหนึ่ง จดว่าอาการเกิดเฉพาะตอนไหน
4. กลับหน้าแรกและหยุดทำงาน 1–2 นาที ดูแนวโน้ม RAM/CPU ไม่ใช้ตัวเลขชั่วขณะครั้งเดียวตัดสิน หน่วยความจำอาจยังเป็น cache โดยไม่ได้ลดทันที
5. ปิดตามปกติ ตรวจใน Task Manager ว่ากระบวนการของตัวทดสอบปิดลง แล้วเปิดใหม่ดูข้อมูลรอบสุดท้าย

ไม่มีเปอร์เซ็นต์ลด RAM ที่รับประกันสำหรับเครื่อง 8 GB/16 GB เป้าหมายคือข้อมูลครบ การเขียนตอบสนองดี และทรัพยากรไม่เพิ่มต่อเนื่องจนเครื่องใช้งานไม่ได้

## แจ้งผลกลับ

ถ้าพบปัญหา จดรุ่น Surface/RAM, Windows scaling, หมายเลขขั้นตอน, ขนาด/จำนวนหน้าไฟล์, ทำอะไรเป็นลำดับ, เกิดซ้ำได้หรือไม่ และเวลาเกิด พร้อมภาพหรือคลิปสั้น ข้อมูลวินิจฉัยของตัวทดสอบอยู่ที่ `%APPDATA%\BetterNote-Sol-Prework\Profile\diagnostics`

สถานะบั๊กที่เลื่อนการแก้: กรณี Worker `messageerror` ระหว่างนำเข้า `.bnote` ยังไม่ได้แก้ตามคำขอ พบจากการจำลองข้อผิดพลาด ยังไม่ยืนยันว่าเกิดกับไฟล์ปกติหรือเป็นสาเหตุ crash เดิม หากนำเข้าค้างและงานอื่นรอ ให้บันทึกเหตุการณ์ก่อนปิด–เปิด แล้วตรวจคลังว่าสมุดเข้ามาแล้วหรือยัง ก่อนกดลองใหม่
