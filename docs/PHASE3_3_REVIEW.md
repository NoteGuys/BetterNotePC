# เฟส 3.3 — รับงานข้ามเครื่องและรักษาสองฉบับเมื่อแก้ชนกัน

สถานะ: พัฒนาและทดสอบด้วยข้อมูลจำลองแล้ว หยุดให้ผู้ใช้ตรวจ ก่อนเริ่ม 3.4
วันที่: 7 ตุลาคม 2026
จุดเซฟก่อนเริ่ม: e75440c (ปรับกู้คืนและหน้า Drive) บน sol-work; งาน 3.3 ยังไม่ commit/push

## สิ่งที่เปลี่ยนสำหรับผู้ใช้

- เครื่อง B รับเนื้อหาใหม่ของสมุดเดิมจากโฟลเดอร์ Google Drive for desktop ได้ โดยเทียบรหัสสมุดและฐานฉบับที่เคยยืนยันร่วมกัน ไม่ข้ามเพียงเพราะมีสมุดอยู่แล้ว และไม่เลือกผู้ชนะด้วยเวลาของเครื่อง
- ถ้าทั้ง A และ B แก้ไข ระบบเก็บฉบับใน B เป็นสมุดใหม่ชื่อ “Copy from this device” ตามภาษาที่เลือก แล้วรับฉบับจากโฟลเดอร์เข้า ID เดิม สมุดสำเนาและหน้ามี ID ใหม่ ทั้งสองฉบับเซฟพร้อมกันใน transaction เดียว
- ตอนเปิดหน้าเขียน หรือมีงานที่ยังเซฟไม่สำเร็จ ระบบรอรับงานก่อน สำรอง Local ยังทำงานตามเงื่อนไขเดิม เมื่อกลับ Documents จะเริ่มตรวจอีกครั้งหลังประมาณ 1 วินาที
- ตรวจข้อมูลย่อทุก 60 วินาทีขณะหน้าต่างมองเห็น ถ้าไม่มีการเปลี่ยนแปลงจะไม่อ่านหน้าหรือเขียนไฟล์สำรองซ้ำ โหลดเนื้อหาเฉพาะสมุดที่เปลี่ยน ครั้งละหนึ่งสมุด ผ่าน native worker และ recovery worker
- หน้าสำรองแสดงกำลังตรวจ/รับงาน/รอ/เก็บสำเนา/ชุดสำรองยังไม่พร้อม รองรับ en/th/zh/ru ยังคงระบุว่าการเขียนลงโฟลเดอร์ไม่ได้ยืนยันว่าอัปโหลดขึ้นคลาวด์เสร็จ

## การป้องกันข้อมูล

- ตรวจ hash และรหัสสมุดของไฟล์จริง พร้อมตรึง manifest ระหว่างอ่าน ก่อนติดตั้งไฟล์สำรองตรวจว่าชุดปลายทางยังตรงกับที่อ่านมา ถ้าเปลี่ยนจะหยุดเฉพาะ Drive
- ก่อนเปลี่ยน IndexedDB ตรวจฉบับเดิมและโฟลเดอร์ที่เลือกใน transaction เดียวกับข้อมูลและฐานฉบับร่วม ถ้าเปลี่ยนระหว่างทางจะ abort ทั้งรายการ
- รับการแก้ไขที่เวลาจากเครื่องต้นทางเก่ากว่าได้ Local backup ยอมรับเฉพาะเมื่อมี hash ของฉบับเดิมที่ยืนยันไว้ ไม่เปิดให้เขียนทับข้อมูลเก่าโดยอาศัยเวลาอย่างเดียว
- การสำรองที่หยุดกลางทางมีรายการงานที่เริ่มไว้และเจ้าของ เครื่องเดิมทำต่อได้เมื่อ hash ตรง เครื่องอื่นรอชุดที่เสร็จแล้ว
- การลบถาวรจากชุดสำรอง Drive ต้องยืนยันว่าฉบับนั้นเคยรับแล้ว จึงไม่ลบงานอีกเครื่องที่ยังไม่รับ ไม่เผยแพร่การลบไปลบสมุดบนเครื่องอื่นอัตโนมัติ
- คง Undo ของสมุดอื่น ล้างเฉพาะสมุดที่รับเข้า ไม่เปลี่ยนเครื่องมือปากกา Canvas การเลื่อนหน้า หรือ OAuth
- หาก renderer ใหม่ทำงานกับ native process เก่า ให้เปิดแอปใหม่เพื่อใช้ sync protocol ใหม่ ระหว่างนั้นยังสำรอง Local ได้

## ข้อจำกัดและจุดตรวจต่อ

- Google Drive for desktop เป็นตัวอัปโหลดและดาวน์โหลด BetterNote ตรวจเฉพาะไฟล์ที่เห็นในเครื่อง ไม่สามารถรับประกันการเรียงลำดับการอัปโหลดระหว่างหลายเครื่องจาก Google ได้
- ถ้า backup รุ่นเก่าไม่มีข้อมูลยืนยันชุดที่เสร็จแล้ว ให้ใช้ Restore ตรวจข้อมูลก่อน แล้วเลือกโฟลเดอร์ Drive ว่างใหม่ ไม่เขียนทับชุดเก่าระหว่างเปิดรับงานอัตโนมัติ
- ไม่ลบสมุดบนเครื่องอื่นเพียงเพราะหายไปจากโฟลเดอร์ ไม่ผสานเส้นปากกาสองฉบับเข้าหน้าเดียว และไม่เปลี่ยนชื่อ/การตั้งค่าโฟลเดอร์เดิมอัตโนมัติ
- ยังไม่ได้ทดสอบย้ายเครื่องจริงผ่าน Google Drive ครบเส้นทาง งานนั้นคือ 3.4 หลังผู้ใช้ตรวจ 3.3 แล้วเท่านั้น

## ให้ผู้ใช้ตรวจ 3.3

1. ปิดและเปิด BetterNote รุ่นที่บิลด์ใหม่นี้ เลือกโฟลเดอร์ Google Drive for desktop เดียวกันบนสองเครื่อง และรอแอป Drive ดาวน์โหลดครบ
2. เขียนสมุดทดสอบใน A แล้วกลับ Documents ให้สำรองเสร็จ ใน B กลับ Documents ตรวจว่ารอยเขียนของสมุด ID เดิมเข้ามาโดยไม่กด Restore
3. แก้สมุดทดสอบเดียวกันทั้งสองเครื่องก่อนรับงาน ตรวจว่าระบบเก็บสำเนาของเครื่องที่รับและฉบับจาก Drive ครบ แล้วตรวจข้อความสถานะใน Backup & Sync

การตรวจผู้ใช้ยังไม่แทนการทดสอบย้ายเครื่องทั้งหมดใน 3.4 ใช้สมุดทดสอบก่อน งานใน Git ยังรอแสดงรายการและคำว่า “ตกลง” ตามขั้นตอนเซฟของผู้ใช้
